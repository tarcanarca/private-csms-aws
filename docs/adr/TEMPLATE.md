## Status

Proposed | Accepted | Superseded by NNNN

Keep exactly one of these values.

## Date

Date the ADR was accepted (YYYY-MM-DD). If it cannot be verified, write an **Assumption:** line, for example the merge date of the pull request that adds this ADR.

## Deciders

Who made the decision (roles or names). If not verifiable, write an **Assumption:** line to be confirmed in pull request review.

## Context

The situation that forces a decision. State what is true today and verify it against the repository, naming files and functions. Keep facts separate from assumptions.

## Decision

What is decided, in plain sentences. Use a numbered or labelled list when there are several rules. Say what this ADR does not change.

## Alternatives considered

| Alternative | Why not chosen |

| Option A | Reason |
| Option B | Reason |

## Consequences

- What becomes easier or harder.
- Follow-ups that are not part of this ADR.
- Documents or code that must be updated with this decision.
